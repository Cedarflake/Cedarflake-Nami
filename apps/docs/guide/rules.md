# Manage rules

When creating a rule, do not begin with the field names. Begin with the browser: what should happen to the address bar after someone opens this path?

## Redirect one path: `exact`

`exact` matches only the complete path you entered.

```text
/docs        → match
/docs/setup  → no match
```

Use it for a normal short link, a campaign entry point, or one fixed legacy URL. Start with `302` or `307` while testing. Move to `301` or `308` only when the destination is stable, because browsers may retain permanent redirects for a long time.

## Move a path tree: `prefix`

`prefix` matches the path and everything below it.

For a `/old` rule targeting `https://new.example.com` with path appending enabled:

```text
/old          → https://new.example.com/
/old/install  → https://new.example.com/install
```

This works well for site moves, renamed directories, and groups of legacy links with the same shape. Turn path appending off when every match should land on one destination.

## Keep the public URL: `proxy`

`proxy` makes the Runtime request the upstream on behalf of the browser. The visitor continues to see the public Runtime domain:

```text
Browser opens https://go.example.com/images/a.jpg
Runtime requests https://image.example.com/a.jpg
```

The transparent default preserves application-level request information, including the method, body, Cookie, Authorization, Origin, and Referer. Hop-by-hop headers are still removed. Separate upstream `Set-Cookie` headers are preserved and their Domain attributes are handled for the public proxy host.

Most services you control do not need further options. Open **Advanced reverse proxy** only when the upstream explicitly requires a fixed Referer, an extra header, a shorter timeout, or different redirect behavior. Provider request-size and execution-time limits still apply.

## Common WebUI fields

- **Path** must start with `/`. A group name organizes the editor and is never prefixed to the public path.
- **Description** is for administrators only. It does not affect matching and is not sent to visitors.
- **Analytics ID** is generated by the WebUI. Keep it when changing the path or destination to preserve the same analytics history.
- **Priority** matters only when several rules can match. Lower numbers run first.
- **Status** belongs to redirect rules. A `proxy` rule does not return a redirect status.

When rules are stored in the database, confirming the dialog saves immediately and creates a new revision. Page-level staging, undo, redo, and **Save changes** return only if you deliberately switch to the GitHub Contents storage plugin.

## When you need the JSON editor

The visual editor covers routine fields. Raw JSON is mainly useful for compatibility checks, bulk inspection, or a GitHub-backed workflow.

Here is a compact example:

```json
{
  "$schema": "https://raw.githubusercontent.com/Revaea/i0c.cc/main/packages/config/redirects.schema.json",
  "Slots": {
    "Main": {
      "/docs": {
        "type": "exact",
        "target": "https://docs.example.com",
        "status": 302,
        "description": "Project documentation"
      },
      "/old": {
        "type": "prefix",
        "target": "https://new.example.com",
        "appendPath": true,
        "status": 308
      },
      "/images": {
        "type": "proxy",
        "target": "https://image.example.com",
        "appendPath": true
      }
    }
  }
}
```

`Slots` may contain named groups; legacy `slots` and `SLOT` roots remain compatible. A string value is still shorthand for a prefix redirect, but an object is easier to maintain because it can carry a description, priority, and stable analytics ID.

The shared Schema rejects unknown fields and validates destinations, statuses, and proxy options before a save. The complete advanced contract lives in the WebUI form and `packages/config/redirects.schema.json`.

If a saved rule still returns the old response, allow one rule-cache interval before following [troubleshooting](/operations/troubleshooting) for snapshot-source and secret checks.
